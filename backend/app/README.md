# FastAPI アプリケーション構造

このディレクトリには、FastAPIアプリケーションの主要なコンポーネントが含まれています。

## ディレクトリ構成

### 📁 routers/
APIエンドポイントの定義とルーティングを管理するディレクトリです。

- **役割**: HTTPリクエストを受け取り、適切なビジネスロジックを呼び出してレスポンスを返す
- **ファイル構成**:
  - `test.py` - テスト用のAPIエンドポイント
  - `attendance.py` - 勤怠管理（出勤・退勤）関連のAPIエンドポイント
  - `sheets.py` - Google Sheets連携関連のAPIエンドポイント
- **特徴**: 各ルーターは独立したモジュールとして管理され、`main.py`で統合される

### 📁 services/
ビジネスロジックと外部サービスとの連携を管理するディレクトリです。

- **役割**: データ処理、外部API連携、複雑なビジネスロジックの実装
- **ファイル構成**:
  - `google_sheets.py` - Google Sheets APIとの通信処理
- **特徴**: ルーターから独立したビジネスロジックを実装し、再利用性を高める

### 📁 models/
データモデルとスキーマ定義を管理するディレクトリです。

- **役割**: Pydanticモデルの定義、リクエスト/レスポンスのスキーマ管理
- **用途**:
  - APIのリクエスト/レスポンスボディの型定義
  - データベースモデルの定義
  - データバリデーションルールの定義
- **特徴**: 型安全性を保証し、自動的なAPIドキュメント生成に貢献

### 📁 config/
アプリケーションの設定と環境変数を管理するディレクトリです。

- **役割**: 環境ごとの設定管理、定数の定義、環境変数の読み込み
- **用途**:
  - データベース接続設定
  - 外部APIのエンドポイント設定
  - アプリケーション全体で使用する定数
- **特徴**: 環境（開発/ステージング/本番）ごとに異なる設定を柔軟に管理

## データフローの例

```
1. クライアント → HTTPリクエスト
2. routers/ → リクエストを受け取り、バリデーション
3. services/ → ビジネスロジックの実行、外部API連携
4. models/ → データの型チェックと変換
5. routers/ → レスポンスの整形
6. クライアント ← HTTPレスポンス
```

## ベストプラクティス

1. **責任の分離**: 各ディレクトリは明確な責任を持つ
2. **依存関係の方向**: routers → services → models の順で依存
3. **テスタビリティ**: 各層を独立してテスト可能に設計
4. **拡張性**: 新機能追加時は同じ構造に従って実装
